# AI安全事件响应

## 触发与止损

触发：敏感数据外发、跨租户读取、未经批准工具动作、严重风险扩散或大规模误杀。记录业务、严重度、影响范围和当班负责人。

先撤销危险工具权限或暂停相关执行，保留受影响版本与脱敏证据；保护正常业务可用性。不要销毁日志，也不要为解释事故继续执行不必要的外部动作。

## 证据

事件ID、发生时间、模型/政策/Prompt版本、用户身份引用、检索来源、工具参数、批准记录、执行回执、出站目的地、受影响对象、恢复与通知情况。

## 定位

分别检查：用户请求有害、外部注入、模型幻觉、权限错误、工具逻辑、输出加载、缓存串租户、策略配置、人审误判、日志缺失。不要因模型说“已拒绝”就认定工具未执行。

## 恢复与回归

修复边界 → 风险与正常对照回归 → 留出评测 → 小流量恢复 → 监测 → 复盘。写明影响仍未确认的部分、控制负责人和完成日期。需要通知用户、合作方或监管时由对应责任部门按事实与适用要求处理。

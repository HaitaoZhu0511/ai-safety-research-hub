# 上下文、多模态与级联审核方法

这是本项目设计建议，核验日期2026-10-01；没有部署真实检测器或人审队列。

## 三条线不要混成一个分数

内容安全线判断对象与语境；Agent安全线判断来源信任、任务偏移和动作权限；业务规则线判断资格、证据和政策。三条线使用各自证据，组合为业务决定，而非将几个厂商分数直接相加。

公开方法入口：[Anthropic两级分类](https://www.anthropic.com/research/next-generation-constitutional-classifiers)、[Microsoft Prompt Shields](https://learn.microsoft.com/en-us/azure/ai-services/content-safety/concepts/jailbreak-detection)、[OpenAI工作流安全](https://developers.openai.com/api/docs/guides/agent-builder-safety)。内部模型方法、预览产品与可迁移架构思想不等价，版本和支持范围必须分别核实。

## 内容覆盖矩阵

每个对象版本记录画面采样、音轨、ASR、OCR、字幕和上下文覆盖。缺失、失败、超时、不同步单独编码为unknown/error，不能把缺值补成低风险分数。

| 输入情况 | 初步策略建议 | 验收依据 |
| --- | --- | --- |
| 常规内容且全部必要模态已覆盖 | 低成本检测，保留抽检 | 真实分布漏放、正常完成 |
| 敏感词但教育/虚构语境 | 上下文判断或疑难人审 | 正常近邻，不仅关键词 |
| 音画/字幕冲突、跨帧语义 | 联合时间区间复核 | 对齐后的对象与时间证据 |
| 模态缺失或采样未覆盖关键段 | 补充检测或转审 | 覆盖状态而不是模型自信 |
| 高影响处罚或权利争议 | 专家/独立批准 | 适用政策、有效证据及回执 |

腾讯文档的[截帧审核](https://cloud.tencent.com/document/product/436/134929)提供画面路径，不应解释为完整音画语义。Meta的[Llama Guard 4说明](https://dev.meta.ai/llama/docs/model-cards-and-prompt-formats/llama-guard-4)则有文本图像联合输入、英语优化和生成图像支持边界；不能默认用于中文生成漫剧全部素材。模型支持“图像”不是所有类型图像均在适用范围。

## 级联设计与反向验收

轻量筛查负责找到需升级的内容，强模型/人审负责细化结论。对一级通过样本抽检，估计其漏掉的风险；对升级样本观察最终正常占比，估计额外负担；对自动限制样本抽检，估计误处置。阈值由业务基线和严重度决定，不照抄论文百分比。

级联成本可用N×(一级单件成本 + 升级比例×二级单件成本 + 人审比例×人审单件成本)加平台/重试/申诉估算。比例必须来自同一流量口径，二级召回须连同一级漏过样本计算。降低升级率但增加严重漏放不是增效。详见[两级分类Case](../cases/classifiers-cascade.md)。

## 不可信数据如何进入工作流

外部文档、工具结果和用户输入保留来源，不升为系统级指令；只提取被校验的结构化业务字段。Microsoft的Spotlighting预览用编码区分低信任文档，但文档注明Token可能增长且支持范围有限；这是输入防护，不是数据权限或工具批准。

检测detected与处置filtered分开统计。工具提案即使语气正常、输入检测通过，仍检查租户、目的地和动作批准；只看“检测命中”会高估实际阻断。

## 流式与检测失败

[OpenAI Moderation文档](https://developers.openai.com/api/docs/guides/moderation)说明完整生成后才有流式审核分数，且工具描述/Schema不在该审核内容范围内。平台若要输出前门禁，应明确缓冲、分段或受限输出策略；本项目没有实现这些策略。不要宣称事后发现能撤回已经传送的内容。

高影响任务在检测错误/超时时转受限或人工；低影响路径采用预先批准的降级。错误类型、延迟和实际暴露时长进入同一Trace，但不能让日志默认保存敏感原文。

## 发布与收益

影子 → 正常/风险切片复核 → 小流量灰度 → 联合验收质量与成本 → 批准扩大。留出集按资产/主体/风险簇去重，避免近似内容泄漏。新模型、语言、政策、采样或素材来源改变均触发适用范围复核。

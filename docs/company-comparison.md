# 大厂AI安全实践对照

## 先区分三个层面

模型公司承担能力研究与训练安全；云厂商提供可集成防护；消费平台承担发布、传播、交易和用户权益治理。同一家企业可能同时涉及多层，不宜按一项工具统一排名。

| 公司 | 公开核心 | 业务结合 | 要避免的误读 |
| --- | --- | --- | --- |
| [OpenAI](../companies/openai.md) | 输入/输出/工具Guardrail与人工批准 | 知识库、客服、取数、工具型Agent | 仅首个/最终Agent上的Guardrail覆盖范围有限；业务仍需独立实现授权与出站约束。 |
| [Anthropic](../companies/anthropic.md) | 风险治理、分类器与行为评测 | 前沿模型发布、安全评测、长任务Agent | 受控模拟结果不能外推为生产事故率；风险框架首页不能替代具体版本全文。 |
| [Microsoft](../companies/microsoft.md) | 企业内容安全与AI红队 | 企业Copilot、办公RAG、审核工作台 | 检测器无法独立解决权限、敏感数据访问和浏览器外发问题。 |
| [Google / DeepMind](../companies/google.md) | 组织基线与模型能力风险 | 企业AI网关、RAG、多业务统一保护 | 模型能力框架与云产品属于不同层；单轮检测不等于完整多轮任务安全。 |
| [Meta](../companies/meta.md) | 开放安全模型与评测工具 | 自部署模型、开放模型应用、代码安全 | 开放权重不等于无限制许可证；工具支持与版本需逐组件核对。 |
| [Amazon Web Services](../companies/aws.md) | 模型解耦的Guardrail服务 | 多模型应用、RAG、安全网关 | 内容过滤结果不能代替数据库ACL、IAM授权和工具副作用控制。 |
| [NVIDIA](../companies/nvidia.md) | 五段式Rails与联合评测 | RAG、工具Agent、领域对话系统 | Rails是编排能力，不自动保证检查逻辑正确；完整配置仍需评测。 |
| [阿里巴巴 / 阿里云](../companies/alibaba.md) | 安全运营Agent与空间隔离 | 审核策略运营、多团队模型平台 | 产品文档公开预览状态；政策调优当前范围有限；一键应用仍应结合自身发布门禁。 |
| [字节跳动 / 火山引擎](../companies/bytedance.md) | 模型入口、认证、配额与可观测 | 多部门模型接入、客服、营销模型服务 | 网关文档不证明字节内部对齐训练；页面标明邀测，不承诺普遍可用。 |
| [腾讯 / 腾讯云](../companies/tencent.md) | LLM WAF与路由防护 | 智能客服、模型服务、Agent平台 | 产品说明未披露生产成功率；不能据营销描述承诺绝对防护。 |
| [百度 / 百度智能云](../companies/baidu.md) | 大模型与Agent安全护栏 | 生成内容、智能问答、企业Agent | 产品描述不提供可直接横比的评测结果；实际支持需按部署场景验证。 |
| [快手 / 可灵AI](../companies/kuaishou.md) | 内容生态、AIGC标识与商业治理 | 短视频、直播、电商、广告、生成视频 | 企业披露效果不是独立因果实验；制度名称不等于公开内部实现。 |

## 六个可复用工程模式（归纳）

1. **身份与数据权限先行**：检索和工具执行使用实际用户身份，模型看到的数据不得扩大授权范围。
2. **防护与模型解耦**：分类器、规则、权限和审批由独立控制服务提供，替换模型时不丢失策略。
3. **检查贴近动作**：工具参数、目的地和金额必须在实际执行前检查；输入安全不代表动作安全。
4. **版本与灰度发布**：政策、模型、Prompt、阈值和工具配置均保存版本；影子运行估算影响。
5. **风险与可用性一起评测**：严重漏放、误杀、正常完成率、延迟、成本采用相同切片观察。
6. **持续学习而非直接自更新**：反馈进入样本准入、专家标注和留出评测，通过批准后再上线。

## 学习顺序

工程落地可先读OpenAI工具批准、AWS版本和NVIDIA Rails；安全运营可先读Microsoft红队、阿里云运营Agent；内容业务可先读快手商品前置和AIGC标识；模型治理再读Anthropic与DeepMind公开框架。

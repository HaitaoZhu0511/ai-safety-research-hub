# 来源维护、版本和事实分级

## v0.4本轮材料

2026-10-01新增15条来源、6个Case和7条带明确日期的动态，见[研究增补](../news/2026-10-01-research-roundup.md)。总计54条来源；仅新来源和实际复核的原火山AgentKit条目记录本次读取日，其他旧来源保持原日期。

OpenAI、Meta、AWS等读取指定网页或README，不能据此声称全部配套论文/API均已核验。Anthropic2026-09材料只读取HTML概览；火山两条材料仅取得官方搜索索引，直接正文返回JavaScript提示。月份未知日、可变README和公告/文档更新日分别处理，不制造发布日期。

本轮按事实 → 范围限制 → 业务建议 → 待执行回归整理。厂商披露、受控研究与产品说明分别登记；旧的实测控制报告不附会为新案例的测试结果。

## 记录规范

每条来源保留publisher、title、url、verified_at、access_status和note。发布日、版本年份、文档更新日、本次读取日分别记录，未知则注明。search_excerpt表示只取得官方搜索索引，不能等同直接正文。需要JavaScript或无法访问的记录必须附限制。

同一功能在不同地域、计费、SDK和产品版本可有差异；产品页面说明不是效果数据。厂商营销数字标注数据口径、观察窗口和是否有对照；模拟、真实试验、漏洞披露与真实入侵分别标注。

## 变更台账

使用[复核台账](../catalog/source-review.json)记录本次证据范围、版本线索和下一步核验。当前未归档完整网页快照，不提供内容哈希或历史差异；后续只有获得许可并实际保存必要证据时再填写snapshot_ref和hash。

人工更新时先核验来源，再修改观点和用例，执行验证后提交。不可为了显示新鲜把旧材料的verified_at批量改成今天，也不把HTTP200视为正文可读。

## 未来采集机制

候选来源 → 来源信任筛选 → 正文变化摘要 → 人工事实核对 → 相关公司/案例/风险映射 → 回归 → 发布。抓取只产生待审候选，不自动写政策或事实结论。尚未创建定时任务；如需监控需另行确定频率和通知范围。

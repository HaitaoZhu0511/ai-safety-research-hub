# v0.3控制修复、验证与契约迁移

日期：2026-09-30。本文描述本仓库离线演示的实际修复，不是某家厂商的内部实现或生产效果报告。

## 修复一：并发重试不再重复执行

旧实现先查内存回执，再执行、写入回执。两个线程可能都在回执尚未写入时通过检查，造成同一批准请求执行两次。顺序重试通过不能证明并发幂等成立。

现在同一个SafetyEngine实例使用可重入锁，把授权、幂等检查、合成执行、回执写入和审计追加放在同一临界区。批准、事件快照、政策替换与停用开关也经同一锁，避免事件序号、链头和政策快照交错。

回归覆盖：16线程同时重试，只有一次合成执行、一个回执，另15次读取缓存；同ID不同提案并发，只能有一个执行，另一个幂等冲突；并发批准保持事件链连续。测试不依赖线程胜出顺序。

适用边界是**同一个实例的线程**，不是多实例、多进程、重启恢复或外部系统的exactly-once。实例A、B各自执行同ID的限制用例仍明确得到两次执行。重启后旧批准被判为approval_unknown，不继续执行，但重新批准后没有历史回执阻止重复。

当前锁只适合短时间合成计算。停用或政策更新等待当前临界区结束，不撤销已完成动作，也不抢占正在执行的动作。不能照搬为持锁等待人审或真实网络调用的生产设计。

## 修复二：事件风险分类进入断言

旧实现将绝大多数非allow事件标成tool-authority，导致预算拒绝、目的地拒绝等虽然被正确阻断，风险看板却统计错类。现在按控制原因分类：

| 原因 | 实际事件risk_ids | 解释 |
| --- | --- | --- |
| tenant_mismatch、metric_not_allowed、destination_denied | privacy | 租户/受保护数据范围/出站边界 |
| row_budget | resource-abuse | 导出数量和类型预算约束 |
| kill_switch | model-governance | 管理面紧急停用 |
| 其他拒绝或转审原因 | tool-authority | 工具及批准授权边界 |
| allow | 空数组 | 没有在该次控制决定中检出风险 |

这是一套有限的确定性理由映射，不是内容分类器。metric_not_allowed也不证明请求一定含PII；它说明请求越过当前指标白名单。生产需细化业务子类型与版本，而非把映射作为所有风险的通用分类标准。

Golden中顶层risk_ids仍是**用例的设计覆盖标签**；expected.risk_ids是**最后一条实际事件的预期标签**，与observed.risk_ids逐项比较。G08覆盖外部指令参数隔离，但运行时检出的是非法参数，不能据此宣称识别了自然语言注入。G19覆盖政策变更，而通用approval_mismatch仍记授权风险，不凭一个通用理由假装知道具体变化类型。

已重跑24个控制用例，全部通过。另有负向测试故意提供错误的风险标签，即使决定、理由和执行次数正确，也必须失败。结构校验要求每个用例提供语义标签断言；它不能替代实际运行。

## 修复三：区分请求者与审批人

0.3事件新增三个必需字段，并保留原identity_ref：

| 字段 | 含义 | 批准事件示例 | 执行/缓存重试示例 |
| --- | --- | --- | --- |
| identity_ref | 提案请求者，保留原语义 | analyst_a | analyst_a |
| actor_ref | 本次事件的操作人 | reviewer_a | analyst_a |
| actor_role | 操作职责，不是完整IAM角色 | reviewer | requester |
| approved_by | 原批准记录的审批人，没有批准则为null | reviewer_a | reviewer_a |

批准事件保留approval_ref；确切执行与缓存重试沿用该引用，重试不再丢失审批链路。批准失配或过期的已知引用也可用于追溯，但不代表当前提案获准。聚合取数不会采用调用端随意附带的批准引用，避免误记“已获某人授权”。

Schema验证必需字段和条件形状；运行时测试另验证请求者、审批人和引用之间的关系。JSON Schema本身不验证审批人身份、同租户或两字段值相等。注册表仍是假身份，不是认证。

## 0.2到0.3的迁移

当前契约：[risk-event.schema.json](../contracts/risk-event.schema.json)。历史契约：[0.2存档](../contracts/archive/risk-event-0.2.schema.json)。

1. 消费者按schema_version分派验证器，再升级报表字段与原因分类版本，不能把0.2事件直接送给0.3验证器。
2. 不覆盖历史事件，也不为旧事件猜测actor_ref或approved_by。缺少可信审批证据时标为“历史不可恢复”，不是改成请求者审批。
3. 旧链需按原始字段校验；任何迁移视图保留原事件引用。改写事件后重算链不等于原始证据。
4. 风险报表注明口径变更日，分段观察，不把privacy/resource-abuse数量增长误判为真实风险增长。
5. 版本切换先用样本契约测试、影子消费和回退演练；本仓库没有实际在线消费者，以上是接入建议。
